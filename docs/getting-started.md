# Getting started

This walkthrough uses the project generated by PatchSim itself. The commands and
paths below are checked against the current CLI.

## Install

Install the published package:

```bash
python -m pip install patchsim
```

For a source checkout:

```bash
git clone https://github.com/dsih-artpark/patchsim.git
cd patchsim
uv sync --extra dev --frozen
```

The rest of this page uses `patchsim`. Replace it with `uv run patchsim` when
working from the source checkout.

## Create a project

```bash
patchsim init first-sim
cd first-sim
```

The default `sir` template creates:

```text
config.yaml
data/
  networks/network-static.csv
  patch/patch-population.csv
  seeds/seed-initial.csv
output/
```

The generated project contains two patches, `A` and `B`. Patch `A` starts with one
infectious individual; patch `B` starts fully susceptible. The network file
contains within-patch and cross-patch weights. The generated configuration uses
`Solver: ode` and `TimeStep: 1.0`.

Choose another built-in template with `--template`:

```bash
patchsim init first-seir --template seir
```

Available names are `sir`, `seir`, `sirs`, and `sis`.

## Validate the inputs

Run validation before every simulation:

```bash
patchsim validate -c config.yaml
```

A valid generated project prints:

```text
Configuration is valid: config.yaml
```

Validation loads the referenced CSV files. It checks compartment names,
non-negative seed values, seed totals, transition identifiers, patch identifiers,
and network weights.

## Run the simulation

```bash
patchsim run -c config.yaml
```

The generated SIR project uses `TMax: 60` and `TimeStep: 1.0`, so the CSV
contains reporting times `0.0` through `59.0`. The first row is the seed state:

```csv
time,S_0,I_0,R_0,S_1,I_1,R_1
0.0,999.0,1.0,0.0,500.0,0.0,0.0
```

The output is written under the generated configuration's `OutputDir`:

```text
output/first-sim/
  logs/first-sim_run_YYYYMMDD_HHMMSS.log
  plots/patch_timeseries_first-sim_ode.png
  runs/all_patches_first-sim_ode.csv
```

`0` and `1` in the CSV columns refer to the order of patches in
`data/patch/patch-population.csv`.

:::{important}
Running the same `ModelName` into the same `OutputDir` overwrites the CSV and PNG.
The log is timestamped and is not overwritten. Use a distinct `OutputDir` for each
scenario or run identity that must be retained.
:::

## Use JSON output

Validation and run summaries can be emitted as JSON:

```bash
patchsim validate -c config.yaml --json
patchsim run -c config.yaml --json
patchsim list-models --json
```

JSON is written to standard output. Runtime logs use standard error and the
timestamped log file, so a caller can capture the JSON stream independently.
The run summary contains artifact paths; the time series remains in the CSV.
